# Filesystem MCP Server Architecture

## Overview
The Filesystem MCP Server is a Node.js application that implements the Model Context Protocol (MCP) for secure, tool-based filesystem operations. It exposes a set of tools (APIs) for file and directory manipulation, metadata retrieval, and search, while enforcing strict access controls based on allowed directories.

## Key Components

### 1. Entry Point and Server Initialization
- The main entry point is `index.ts` (compiled to `dist/index.js`).
- The server is started with one or more allowed directories as command-line arguments. Only these directories (and their subdirectories) are accessible for all operations.
- The server uses the `@modelcontextprotocol/sdk` for protocol and transport abstractions, and communicates over stdio by default.

### 2. Tool Configuration
- All available tools and their metadata are defined in `tool-config.json`.
- Each tool can be enabled/disabled, described, and has a JSON schema for its input arguments.
- The server reads this config at startup and exposes only enabled tools.

### 3. Path Validation and Security
- All incoming file/directory paths are validated by the `validatePath` function.
  - Paths are expanded (e.g., `~` to home), resolved to absolute, and normalized.
  - The server checks that the requested path (and any symlink targets) are within the allowed directories.
  - If a path is outside, access is denied and an error is returned.
- This mechanism prevents directory traversal and symlink attacks.

### 4. Tool Handlers
- Each tool (e.g., `read_file`, `write_file`, `list_directory`, etc.) is implemented as a handler function.
- Handlers parse and validate input arguments, call `validatePath`, and perform the requested operation using Node's `fs/promises` API.
- Errors (invalid arguments, access denied, etc.) are caught and returned in a structured format.

### 5. Supported Tools
- **read_file**: Read the contents of a file.
- **read_multiple_files**: Read multiple files at once.
- **write_file**: Write or overwrite a file.
- **edit_file**: Make line-based edits to a file.
- **create_directory**: Create a directory (recursively).
- **list_directory**: List files and directories at a path.
- **directory_tree**: Recursively list directory structure as JSON.
- **move_file**: Move or rename files/directories.
- **search_files**: Recursively search for files/directories by pattern.
- **get_file_info**: Retrieve file/directory metadata.
- **list_allowed_directories**: List all directories the server is allowed to access.

### 6. Deployment
- The server can be run directly with Node.js or via Docker (see `Dockerfile.txt`).
- In Docker, host directories are mounted to `/projects` and passed as allowed directories.
- The server is started with the allowed root(s) as arguments.

### 7. Error Handling
- All errors (invalid arguments, access denied, file not found, etc.) are caught and returned in a structured response.
- Tool calls that fail due to access control or validation do not crash the server.

## Example Flow
1. **Startup**: `node dist/index.js /allowed/dir1 /allowed/dir2`
2. **Tool Call**: Client requests `read_file` with `{ path: "/allowed/dir1/file.txt" }`.
3. **Validation**: Server checks that the path is within `/allowed/dir1`.
4. **Execution**: If valid, file is read and contents returned; otherwise, error is returned.

## Security Considerations
- Only explicitly allowed directories are accessible.
- All symlinks are resolved and checked.
- Parent directories for new files are validated.
- Tool configuration can disable risky operations.

## Extensibility
- New tools can be added by updating `tool-config.json` and implementing a handler in `index.ts`.
- Input validation is handled via Zod schemas, making it easy to extend or modify argument structures.
